Generated: 2026-10-08

IMPORTANT NOTE
This project is a paper-trading and analysis platform. It does not place real broker orders. It fetches market data, scores NSE stocks, opens simulated trades in SQLite, tracks simulated PnL, and shows everything in a React dashboard. It is for education, testing, and strategy research only, not investment advice.


1. PROJECT SUMMARY

Project name:
Atlas Trading / AI Paper Trading Agent for NSE Stocks

Main purpose:
The project watches Indian NSE stocks, collects candle/news/announcement data, calculates indicators, scans the market in two stages, builds trade plans, asks multiple agent modules to evaluate the plan, validates risk rules, opens paper trades, monitors exits, learns from closed trades, and exposes everything through a FastAPI backend and React website dashboard.

Main user-facing website:
The frontend is a React + TypeScript + Vite dashboard in frontend/src. It is not just a landing page. It already has real working pages:
- Overview
- Scanner
- Charts
- News
- Open Trades
- Trade History
- Strategy
- Backtest
- Pipeline

Main backend:
backend/main.py starts a FastAPI app. The frontend calls this API at http://localhost:8000 by default.

Main scheduler:
orchestrator/main.py runs the trading pipeline repeatedly during Indian market hours.

Main database:
database/trading.db is a SQLite database. database/init_db.py creates the schema and seed data.

5. MAIN RUNTIME FLOW WHEN PROJECT IS RUNNING

The orchestrator market cycle does this:
1. Checks whether the market is open, unless run-once or startup cycle bypasses the guard.
2. Fetches 5m and 15m candles through data/fetcher.py.
3. Runs analysis/indicator_engine.py to calculate RSI, MACD, EMA, VWAP, and volume ratio.
4. Runs Stage 1 scanner in analysis/stage1_scanner.py.
5. Fetches missing recent candles for Stage 1 flagged stocks.
6. Runs Stage 2 scanner in analysis/stage2_scanner.py.
7. Builds complete trade plans with brain/strategy_builder.py.
8. Sends trade plans through agents/debate_engine.py.
9. Applies validation with agents/trade_validator.py.
10. Calculates position sizing with agents/risk_manager.py.
11. Opens simulated trades with agents/paper_trader.py unless dry-run is enabled.
12. Monitors open trades for target, stop loss, replacement, or end-of-day exit.
13. Updates account and performance statistics.
14. Writes status to orchestrator/status.json so the dashboard can show scheduler health.

Scheduled jobs:
- Market cycle: every 5 minutes, Monday-Friday, 09:00-15:59 trigger range with market guard 09:15-15:25.
- Hourly candles: every 30 minutes during market hours.
- Daily candles: 09:00 on weekdays.
- Announcement fetch: every 30 minutes during market hours plus premarket 09:10.
- Support/resistance update: every 30 minutes.
- News fetch: every 15 minutes.
- Sentiment processing: every 5 minutes.
- End-of-day trade monitoring: 15:30.
- Weekly learning cycle: Saturday 10:00.
- Universe update: Sunday 09:00.

Safety controls:
- Only one market cycle can run at a time.
- If a cycle exceeds 240 seconds, the next scheduled cycle is skipped.
- If a stage fails 3 consecutive times, that stage is disabled for the current session.
- Dry-run mode prevents opening and closing paper trades.


6. TWO-STAGE SCANNER

Stage 1 file:
analysis/stage1_scanner.py

Purpose:
Quickly scans the broad NSE universe and shortlists symbols for deeper analysis.

What it checks:
- Price movement greater than 0.5%.
- Volume ratio greater than 1.5x.
- Always includes F&O stocks.
- Always includes symbols with open paper trades.

How it gets prices:
- First tries NSE bhav copy CSV.
- Then tries NSE F&O securities API.
- Falls back to latest local candles from SQLite.

What it writes:
- scan_results rows with stage = 1.
- stage1_flagged = 1.
- stage1_price_change.
- stage1_volume_ratio.
- stage1_reason.

Stage 1 output:
- A ranked shortlist of up to 80 symbols for Stage 2.
- The full flagged list is still stored for visibility.

Stage 2 file:
analysis/stage2_scanner.py

Purpose:
Runs detailed scoring only on Stage 1 shortlisted stocks.

What it calls:
- analysis.signal_engine.load_config()
- analysis.signal_engine.get_strategy_weights()
- analysis.signal_engine.detect_market_condition()
- analysis.signal_engine.score_stock()
- analysis.pattern_detector.run_all_patterns()
- analysis.kronos_forecaster.apply_kronos_adjustment()

What it checks:
- Recent or available 15m candle data.
- Technical score.
- Direction BUY/SELL/HOLD.
- Multi-timeframe confluence.
- Pattern detection.
- Optional Kronos forecast adjustment.

What it writes:
- Updates scan_results rows to stage = 2.
- stage2_score.
- stage2_direction.
- stage2_pattern.
- stage2_setup.
- final_selected = 1 when the candidate passes threshold and confluence rules.

Stage 2 output:
- Top candidates sorted by score.


7. SIGNAL SCORING ENGINE

File:
analysis/signal_engine.py

Purpose:
Scores each stock using indicators and strategy weights.

Data source:
- indicators table.
- candles table.
- strategy_rules table.
- analysis/signal_config.json.
- announcement boost from data/announcement_fetcher.py.
- timeframe confluence from analysis/multi_timeframe.py.

Indicators used:
- RSI.
- MACD and MACD signal/histogram.
- Volume ratio.
- VWAP.
- EMA 20 and EMA 50 indirectly through market condition and indicators.

Direction logic:
- MACD gives a BUY/SELL/NEUTRAL hint.
- RSI is used as fallback when MACD is neutral.
- BUY and SELL directions are scored.
- If final score is below hold_threshold, result becomes HOLD.

Score logic:
- Each core signal can score up to 25.
- Strategy weights from strategy_rules are applied.
- Weighted raw score is scaled to 0-100.
- Oversold/overbought and volume confirmation can boost weak signals.
- HIGH timeframe confluence can boost score by 20%.
- Corporate announcement signal boost can add or subtract score.

Result fields:
- symbol.
- direction.
- rsi_score.
- macd_score.
- volume_score.
- vwap_score.
- weighted_score.
- timeframe_confluence.
- announcement_boost.
- market_condition.
- explanation.
- notes.


8. STRATEGY BUILDER AND SETUPS

Files:
- brain/setup_library.py
- brain/setup_matcher.py
- brain/strategy_builder.py

Purpose:
These files turn raw scan candidates into fuller trade plans.

setup_library.py:
- Creates and seeds the setup library.
- Stores setup definitions in the setups table.
- Tracks setup performance stats.
- Defines setup conditions, entry methods, target methods, stoploss methods, preferred market conditions, time windows, and historical performance fields.

setup_matcher.py:
- Reads latest candles, indicators, price structure, patterns, news, and market condition.
- Checks whether a symbol matches active setup definitions.
- Calculates entry price, target price, stoploss price.
- Scores setup quality.
- Can match all Stage 2 candidates.

strategy_builder.py:
- Takes Stage 2 candidates.
- Reads indicators, patterns, levels, news, setup match, and confluence.
- Builds a human-readable reasoning string.
- Builds trade plan dictionaries for debate/execution.

The trade plan includes:
- symbol.
- direction.
- weighted score.
- entry price.
- target price.
- stop loss.
- market condition.
- setup match.
- reasoning.
- news and level context.

debate_engine.py:
- Takes a trade plan.
- Calls multiple specialized agents.
- Collects votes.
- Moderates the result.
- Produces debate_approved, debate_confidence, debate_reason, and debate_votes.
- Persists debate details through agent_memory.py.

market_regime_agent.py:
- Evaluates broad market condition using index momentum and market breadth.
- Can adjust score or veto plans when regime is unfavorable.

news_impact_agent.py:
- Loads recent news/announcements for the symbol.
- Evaluates whether news supports or conflicts with the trade.

sector_rotation_agent.py:
- Looks at sector momentum for the stock's sector.
- Adjusts recommendation based on sector strength/weakness.

execution_quality_agent.py:
- Checks whether current price/entry quality is acceptable.
- Helps avoid poor execution.

fundamentals_analyst.py:
- Reads stored fundamental facts and disclosures.
- Produces a fundamental recommendation and confidence.

trade_review_agent.py:
- Reviews closed trades.
- Stores post-trade analysis in trade_reviews.
- Links outcome back to agent memory.

agent_memory.py:
- Creates agent_memory and agent_debates schema.
- Stores individual agent decisions.
- Stores debate summaries.
- Links debates to trades.
- Marks outcomes after trades close.


10. TRADE VALIDATION, RISK, AND PAPER TRADING

Trade validator:
agents/trade_validator.py

It checks:
- Direction must be BUY or SELL.
- Score must meet active strategy threshold.
- No duplicate open position.
- Available balance.
- Maximum open trade limit.
- Market hours.
- Sideways market permission.
- Logs approval/rejection into trade_logs.

Risk manager:
agents/risk_manager.py

It calculates:
- Entry price.
- Stop loss.
- Target.
- Risk per share.
- Maximum loss amount from risk_per_trade_pct.
- Quantity based on risk.
- Maximum capital per trade.
- Final position quantity.
- Capital required.

Default behavior described in README:
- Risk per trade: 1% of account balance.
- Position capital cap: 20% of current balance.
- Stop loss: about 0.75% away from entry.
- Target: about 1.5% away from entry.

Paper trader:
agents/paper_trader.py

open_trade():
- Validates signal again.
- Ensures paper_trades schema.
- Gets latest candle price.
- Calculates or accepts risk position.
- Prevents duplicate position.
- Checks balance.
- Inserts paper trade as PENDING, deducts capital, then marks it OPEN.
- Stores ML features.
- Links agent debate memory.

monitor_open_trades():
- Reads every OPEN trade.
- Gets latest candle.
- Closes if target is hit.
- Closes if stop loss is hit.
- Closes at end-of-day time.
- Handles missing candle data.
- Updates balance, PnL, outcome, and status.
- Updates ML feature outcome and trade review.

close_trade():
- Manually closes an OPEN trade by ID.
- Used for trade replacement and other exit paths.

Trade replacement logic in orchestrator:
- Dynamic max trades: TRENDING = 8, SIDEWAYS = 6, VOLATILE = 4.
- If account is full, a new strong signal can replace a weak losing open trade.
- Replacement requires score advantage >= 20, existing trade losing more than 0.3%, and new signal score >= 65.
- Replacement exit reason is REPLACED.

23. FINAL SIMPLE EXPLANATION

When the project is running, it works like this:
1. It downloads stock candles and saves them.
2. It calculates technical indicators.
3. It quickly scans the whole NSE universe.
4. It deeply analyzes only the most important symbols.
5. It builds trade plans.
6. It asks multiple internal agents whether the plan is good.
7. It validates rules and sizes risk.
8. It opens simulated trades.
9. It monitors targets, stop losses, and end-of-day exits.
10. It records PnL and performance.
11. It learns from closed trades.
12. It shows everything on the website dashboard.

This is the complete working concept behind the project and the basis for a GitHub README or website presentation.
